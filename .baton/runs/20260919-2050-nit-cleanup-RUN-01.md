  `validateArtifactPath`'s returned error with `%w` instead of discarding it

  block now sets `next = "EXECUTED (delegate Executor)"` as an explicit
  fail-closed default before checking the REVIEW record, instead of relying on

  requested comment, out-of-scope item 8 itself not implemented).

  `review_artifact: unreadable: PATH` to `review_artifact_unreadable: PATH`
  (one key, one value; same position between `branch:` and `next_command:`,
  same emission condition, same path value).
- `internal/baton/lint_test.go`: item 2. Added
  `TestLintRejectsInvalidExecutedArtifact`, `TestLintRejectsInvalidReviewArtifact`,
  and `TestLintRejectsInvalidCloseArtifact`, each driving lint over a log whose
  EXECUTED/REVIEW/CLOSE line has a path that exists on disk but fails
  `checkArtifact` (a bad Status line, an invalid Result, and a missing user
  approval line respectively), asserting lint rejects each. No production code
  changed.
- `internal/baton/commands_test.go`: item 3. Corrected the doc comment on
  `TestPlaceholderCheckFailsClosedWithoutTemplates` to name the three subtests
  that actually exist (missing directory, empty directory, templates without
  placeholders) instead of claiming an "unreadable template file" case that is
  not present. No subtest added, matching the PLAN's decision not to buy that
  coverage with an unreliable mode-000 file. No production code changed.
- `internal/baton/commands_test.go`: item 4. `TestPlaceholderCheckRefusesSinglePlaceholder`
  now uses an explicit token per case, chosen to occur in its own template and
  in no other (plan.md's "what must be true when the task is complete"
  bracketed placeholder; run.md's "met / not met / partial" one; review.md's
  "ready-for-user-decision / blockers" one; close.md's "why the run satisfies
  the plan and success criteria" one; see the test source for the exact
  angle-bracket spellings), instead of reinserting the first token
  `placeholderPattern.FindString` returns (which can occur in more than one
  template). Added an assertion that each token appears in its own template and
  in no other file under `.baton/templates/*.md`, so a future template edit
  that duplicates a token fails the test loudly. No production code changed.
- Items 5, 6, 8 are declined in the PLAN and were not implemented, per Director
  instruction.
