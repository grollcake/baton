## Changes

- `internal/baton/remove.go`: fixed REVIEW-01's N1 in `purgePrecondition`.
  `runGit` (`app.go`) returns `strings.TrimSpace(output)` over the whole
  multi-line `git status --porcelain` output, which strips the leading
  status-column space from the first line only, whenever that line's status
  code is an unstaged one (` M`, ` D`, ...) -- shifting that one line left by
  one byte. The old code unconditionally read `line[3:]` for every line, so
  the first offending path lost its leading byte (`.baton/GUIDANCE.md`
  reported as `baton/GUIDANCE.md`); every later line was unaffected, since
  only the start of the whole trimmed string can be shortened.
  The fix stays at the call site, not in `runGit`: `runGit` trims are relied
  on elsewhere in this file (`ls-files`/`rev-parse HEAD` emptiness and value
  checks) and in `lint.go`'s Git-tracking checks, and changing what `runGit`
  returns for every caller to fix one caller's line-oriented parsing was not
  worth re-auditing every other call site for this round. Every
  `git status --porcelain` line is guaranteed to have its two status
  characters followed by a separator space at index 2; the fix checks that
  invariant per line and only falls back to index 2 (instead of index 3) for
  the first line when the invariant does not hold there, which is exactly
  and only the one-byte shift `runGit`'s whole-string trim can produce. No
  other line is treated differently, so a fix that only special-cased "the
  first line" as a location rather than as a shift would not have needed
  this per-line invariant check -- and the new test's second offending path
  guards against exactly that shortcut.
- `internal/baton/remove_test.go`: added
  `TestPurgePreconditionReportsFullPathForFirstLine`, covering exactly the
  shape REVIEW-01 reproduced: a tracked file modified in the worktree (not
  staged, so its status is ` M`) sorting alphabetically before an untracked
  file under `.baton/`, so the affected line is genuinely first and a second,
  unaffected offending path is also present. It calls `purgePrecondition`
  directly and asserts the blocked list contains the full `.baton/GUIDANCE.md`
  and `.baton/ZZZ-extra.md` paths, and fails explicitly (rather than just
  not-passing) if a `baton/GUIDANCE.md`-shaped truncated path appears instead.

No other file changed. RUN-01 and REVIEW-01 are untouched (append-only); the
other six nits REVIEW-01 raised (N2-N7, listed in Director's message) are
left for Director to record at close.
