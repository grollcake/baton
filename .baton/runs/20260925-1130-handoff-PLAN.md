## Goal

- A session that must stop can seal one record under `.baton/` holding only the
  facts that die with it: branch strategy, user decisions not yet on disk, the
  delegate agents that are gone and the stage each had reached, and what
  Director intended to do next.
- The next session learns the record exists from `baton status`, which it
  already runs, and can tell a live record from one the work has moved past.
- The record is written only when the user asks; nothing writes it
  automatically, and no warning or threshold triggers it.

## Plan

1. Add `templates/handoff.md` in `bootstrap/.baton/templates/` and mirror it to
   `.baton/templates/`. Required shape: `# HANDOFF` title, a `Date:` line, a
   `Log Line:` line, and the sections `## Branch Strategy`,
   `## Unrecorded Decisions`, `## Delegates`, `## Next Intent`. `Date:` and
   `Log Line:` carry placeholder-tokens saying the command stamps them. The
   template states in one line that anything already in `BATON-LOG.txt`,
   `.baton/runs/`, `GUIDANCE.md`, `lesson-learned/`, or `baton models get`
   must not be copied into it.
   Verify: `go test ./...` still passes (`commands_test.go` globs templates).
2. Add `internal/baton/handoff.go`:
   - `runHandoff(args)` parses one flag, `--clear`. `--clear` removes
     `.baton/HANDOFF.md` and prints what it removed; removing a file that is
     not there is an error, not a silent success.
   - Without `--clear` it seals: read `.baton/HANDOFF.md`, refuse with a
     message naming `templates/handoff.md` when it is absent; replace the
     `Date:` and `Log Line:` lines with the stamped values; then refuse if any
     placeholder-token remains (reuse `placeholderPattern`) or any required
     title or section line is missing, writing nothing in that case. Only on
     success write the file back and print its path.
   - `Log Line:` is the `Line` of the last record in `BATON-LOG.txt`, or `0`
     when the log has none. The binary stamps it; Director never supplies it.
   - `handoffState()` returns an explicit outcome plus an error rather than an
     empty value: absent, sealed-live, or superseded, with the recorded line
     and the count of events appended since. A record that cannot be read or
     parsed is reported as unreadable, never as live
     (see `lesson-learned/sentinel-lets-callers-choose.md`).
   Verify: the tests in step 5.
3. Wire `handoff` into `App.Run` and `usage` in `app.go`, under
   "Record and inspect state". Do not add it to `refusesWhilePaused`: the
   record says why a session stopped and delegates nothing, so a paused project
   must still be able to seal and clear one. Name that decision in a comment.
   Verify: `baton help` lists it; `go test ./...`.
4. Report it from `status`. In `runStatus` (both branches) and in
   `reportOpenTasks`, print one line from `handoffState()`:
   - `handoff: .baton/HANDOFF.md | sealed: DATE | read it before acting`
   - `handoff_superseded: .baton/HANDOFF.md | sealed: DATE | N event(s) appended since; clear it with 'baton handoff --clear'`
   - `handoff_unreadable: .baton/HANDOFF.md | REASON`
   - nothing when no record exists.
   A superseded or unreadable record is printed, never hidden, so it cannot be
   mistaken for a live one and cannot sit unnoticed.
   Verify: the tests in step 5.
5. Add `internal/baton/handoff_test.go` with one test per behaviour:
   1. seal refuses when `.baton/HANDOFF.md` is absent and names the template;
   2. seal refuses, and leaves the file byte-identical, when a required section
      is missing or a placeholder-token is still unfilled;
   3. seal stamps `Date:` and `Log Line:` with the current last log line and
      leaves every other line unchanged;
   4. `status`, `status --open`, and `status` with no open task each print
      `handoff:` for a sealed record;
   5. `status` prints `handoff_superseded:` with the event count after one more
      event is appended;
   6. `--clear` removes the record, `status` then prints no handoff line, and a
      second `--clear` fails.
   Verify: `go test ./...`, then `revert-check` per step 8.
6. Add the rule to `bootstrap/.baton/DIRECTOR.md` and mirror it to
   `.baton/DIRECTOR.md`. Keep it to about six lines, in "Director Tools":
   seal a handoff only when the user explicitly asks to stop or hand off;
   fill `templates/handoff.md` with what would otherwise be lost and nothing
   that is already on disk; run `.baton/bin/baton handoff` to seal it; on resume,
   `.baton/bin/baton status` names a sealed record, read it before acting, and clear it
   with `.baton/bin/baton handoff --clear` once its content is either acted on or
   recorded elsewhere. Add no exception clause anywhere else.
   Verify: `.baton/bin/baton lint` after step 7.
7. Bump `VERSION`, `.baton/VERSION`, and `bootstrap/.baton/VERSION` to `0.45.0`
   and run `go run ./cmd/build-release`, which rebuilds every target and
   refreshes this repository's `.baton/bin`.
   Verify: `.baton/bin/baton lint` reports the managed documents and the binary
   checksum as matching.
8. Prove each new test pins its change: for every changed source path run
   `.baton/bin/baton revert-check --check 'go test ./...' --name-pattern '--- FAIL: (\S+)' PATH`
   and record, per test, the `new_output=` reason it fails only after the
   revert.

## Success Criteria

- `.baton/bin/baton handoff` refuses a missing, unfilled, or section-incomplete
  record and writes nothing in those cases.
- A sealed record carries a `Log Line:` the binary stamped from
  `BATON-LOG.txt`, not a value any agent typed.
- `baton status`, `baton status --open`, and `baton status` with no open task
  each surface a sealed record without anyone knowing it exists.
- After one further event is appended, the same record is reported as
  `handoff_superseded:` with the number of events since.
- `baton handoff --clear` removes the record; `status` then reports none.
- `go test ./...` passes; `.baton/bin/baton lint` passes; every new test is
  shown load-bearing by `revert-check`.

## Risks Or Questions

- Staleness has one axis, the append-only log. A handoff sealed for work that
  never appends another event (Solo work, or a session that stops before its
  next event) stays live until someone runs `--clear`. The plan accepts this
  rather than adding a date or commit heuristic, and prints the sealed date on
  every status line so age is visible. Raise it to the user if a second axis is
  wanted.
- `DIRECTOR.md` is embedded in the binary (`docs.go`). Editing it without
  `go run ./cmd/build-release` leaves `baton lint` failing on managed documents;
  step 7 is not optional.
- Not adding `handoff` to `refusesWhilePaused` is a judgment call made here, for
  the reason in step 3. If Director wants a paused project to refuse it, that is
  a one-line change and should be decided before Executor starts.
- The record can hold user decisions in prose. `PROTOCOL.md` already forbids
  secrets and personal data under `.baton/`; the template inherits that and no
  new rule is added for it.
